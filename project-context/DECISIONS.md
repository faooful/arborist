# Decisions

**D1. Swift Package, not an Xcode project.** CLI, core and app are SwiftPM targets (tools 5.9, macOS 13+). Builds with `swift build` on the Mac, and Core + CLI build and test on Linux. The app target is wrapped in `#if os(macOS)`; `scripts/make-app.sh` makes the .app bundle.

**D2. Read-only v1.** No deletes anywhere. Worktree rows offer Reveal in Finder and copying `git worktree remove <path>` (or `git worktree prune` for missing folders) for Joseph to run himself. Clean buttons are deferred and need sign-off.

**D3. No Full Disk Access.** We don't ask for it. Under `~` we skip Library, Desktop, Downloads, Pictures, Movies, Music, Applications and Public unless chosen as roots, which avoids privacy prompts. Docker size comes from `docker system df`, not Docker's container folder. Unreadable paths are skipped and counted.

**D4. CLI JSON for agents.** `arborist scan --json` emits the same `ScanResult` the app renders (sorted keys, ISO 8601 dates, totals included).

**D5. Stale rule.** A linked worktree is stale when its branch has no commits beyond the default branch (origin/HEAD, else main/master) and has moved since creation (so fresh branches aren't flagged), when its upstream is `[gone]`, or when git marks it prunable. The main worktree is never stale.

**D7. Menu bar popover only, no window (Joseph, PR #1).** ArboristApp has no Window/WindowGroup. Everything lives in the `MenuBarExtra` popover (`.menuBarExtraStyle(.window)`): free space, summary, project/worktree list with Reveal and Copy remove command, shared caches, Rescan/Reveal/Settings/Quit. Settings stay a minimal `Settings` scene opened from the popover. Styling is plain pending Dara's popover redesign; the blob view was removed from the app (`BlobLayout` stays in Core, tested, unused for now). The menu bar label stays as free-space text pending Joseph's OK.

**D6. Size split.** Directories named node_modules, .next, dist, target, .venv, DerivedData or .build count as rebuildable; everything else (including .git) is source. Nested repos/worktrees are skipped inside a parent so nothing is counted twice. Sizes are allocated bytes; units are decimal like Finder.

**D8. Renamed to Arborist (Joseph).** App `ArboristApp` / `Arborist.app` (bundle id `com.faooful.arborist`), CLI `arborist`, core module `ArboristCore`, config `~/.config/arborist/config.json`. The GitHub repo is now `faooful/arborist` (renamed from devspace; PR #1 carried over). No migration from the old config path: it never shipped.

**D9. H8 "leaves" design adopted; layout ported to Swift (Joseph approved H8).** The popover (480 pt wide, text ≥ 10.5 pt) is a weighted Voronoi treemap: repo groups, then worktrees inside, each cell inset, smoothed, waved and shaped by kind (worktree lance, main oval, cache fan, app data heart, deps oak), with veins. States: protected (dirty or unpushed) moss, clean sage, stale dried-leaf tan; Free is a stippled field drawn at up to ⅔ of used space so a roomy disk still shows the leaves. The layout lives in `ArboristCore/Leaves` as a deterministic port of h8.js: power-diagram cells via half-plane clipping, sites moved to centroids and weights adapted toward target areas (in place of d3-voronoi-map), SplitMix64 seeded with "arborist", and h8.js's Park–Miller generator for waves and veins. Leaves have a minimum size (28 pt): two or more smaller items in a group fold into "other (n)"; a lone small item is padded up. "Clear N" shows the stale count and stays read-only: it copies the `git worktree remove` commands. Tapping a leaf gives Reveal in Finder and Copy remove command; a List toggle keeps the v1 list (and gives screen readers every item). App data (heart) is supported by the layout but the scanner doesn't produce it yet. `arborist render` writes the same geometry as SVG, for snapshots from Linux.

**D10. Menu bar icon is a wilting leaf (Joseph).** Four monochrome template glyphs (healthy, droop, wilted, dry outline) generated from `LeafGlyph` geometry, so they follow light and dark mode. Stage = free space vs multiples of the low-space alert: healthy above 3×, droop 1.5–3×, wilted 1–1.5×, dry below 1× (a value on a boundary takes the healthier stage). Multipliers are `leafStages` in `~/.config/arborist/config.json`; `showFreeText` (default on) keeps the free-space text next to the icon. Accessibility label: "Arborist: leaf <stage>, <n> GB free". Strip: `project-context/shots/leaf-stages.png`.

**D11. Progressive, bulk-listed, cached and time-limited scans (Joseph's Mac stuck on "Scanning…" for 2+ minutes).** `sample` showed the time going to `DiskUsage.treeSize` in disk wait. Changes:
- **One walk, bulk listing.** `DirLister` lists each directory once: `getattrlistbulk` on macOS (names, types and allocated sizes in one call per batch), `readdir` + `fstatat` on Linux, FileManager with prefetched keys as the fallback. `measureWorktree` sums rebuildable folders as it walks them (nested node_modules/.build inside one are not walked again) and spots nested repos from the listing it already has, with no extra `.git` stat. The per-file `resourceValues(Set)` calls are gone.
- **Linux sizes fixed as a side effect.** swift-corelibs reports allocated size as st_blocks × st_blksize, which is 8× too big on 4 KB-block filesystems. Linux now uses st_blocks × 512, which matches `du`. macOS sizes are unchanged.
- **Progress.** `Scanner.scan(cancel:onEvent:)` and `events(timeout:)` (an AsyncStream) report `.volume` (immediately), `.discovered(n)`, `.repo` as each repo's worktrees all finish, `.caches` and `.finished`. The app shows free space at once, fills the map repo by repo (relayout coalesced to every 0.4 s) and shows "12/34 repos". `scan()` (the CLI) returns the same result and JSON as before.
- **Cache.** The last finished scan is written to `~/Library/Caches/arborist/last-scan.json` (`$XDG_CACHE_HOME`/`~/.cache/arborist` elsewhere). On launch it is drawn immediately and marked "Cached" until the fresh scan finishes. Fresh repos replace cached ones as they arrive. An unreadable cache is ignored.
- **Timeout.** `scanTimeoutSeconds` (default 180) in config. `Deadline.run` runs the scan on its own thread and races it against the deadline. On timeout it sets a `CancelFlag` that the walkers and workers check, and the app shows the error with **Retry**, keeping the last results. The caller never waits on a stuck worker.
- **Sendable warnings.** In `checkLowSpace`, the notification body is built on the main actor before the callback, and `UNUserNotificationCenter` is fetched inside it. Nothing non-Sendable is captured.
