# Decisions

**D1. Swift Package, not an Xcode project.** CLI, core and app are SwiftPM targets (tools 5.9, macOS 13+). Builds with `swift build` on the Mac, and Core + CLI build and test on Linux. The app target is wrapped in `#if os(macOS)`; `scripts/make-app.sh` makes the .app bundle.

**D2. Read-only v1.** No deletes anywhere. Worktree rows offer Reveal in Finder and copying `git worktree remove <path>` (or `git worktree prune` for missing folders) for Joseph to run himself. Clean buttons are deferred and need sign-off.

**D3. No Full Disk Access.** We don't ask for it. Under `~` we skip Library, Desktop, Downloads, Pictures, Movies, Music, Applications and Public unless chosen as roots, which avoids privacy prompts. Docker size comes from `docker system df`, not Docker's container folder. Unreadable paths are skipped and counted.

**D4. CLI JSON for agents.** `arborist scan --json` emits the same `ScanResult` the app renders (sorted keys, ISO 8601 dates, totals included).

**D5. Stale rule.** A linked worktree is stale when its branch has no commits beyond the default branch (origin/HEAD, else main/master) and has moved since creation (so fresh branches aren't flagged), when its upstream is `[gone]`, or when git marks it prunable. The main worktree is never stale.

**D7. Menu bar popover only, no window (Joseph, PR #1).** ArboristApp has no Window/WindowGroup. Everything lives in the `MenuBarExtra` popover (`.menuBarExtraStyle(.window)`): free space, summary, project/worktree list with Reveal and Copy remove command, shared caches, Rescan/Reveal/Settings/Quit. Settings stay a minimal `Settings` scene opened from the popover. Styling is plain pending Dara's popover redesign; the blob view was removed from the app (`BlobLayout` stays in Core, tested, unused for now). The menu bar label stays as free-space text pending Joseph's OK.

**D6. Size split.** Directories named node_modules, .next, dist, target, .venv, DerivedData or .build count as rebuildable; everything else (including .git) is source. Nested repos/worktrees are skipped inside a parent so nothing is counted twice. Sizes are allocated bytes; units are decimal like Finder.

**D8. Renamed to Arborist (Joseph).** App `ArboristApp` / `Arborist.app` (bundle id `com.faooful.arborist`), CLI `arborist`, core module `ArboristCore`, config `~/.config/arborist/config.json`. The GitHub repo is now `faooful/arborist` (renamed from devspace; PR #1 carried over). No migration from the old config path: it never shipped.

**D9. H8 "leaves" design adopted; layout ported to Swift (Joseph approved H8).** The popover (480 pt wide, text ≥ 10.5 pt) is a weighted Voronoi treemap: repo groups, then worktrees inside, each cell inset, smoothed, waved and shaped by kind (worktree lance, main oval, cache fan, app data heart, deps oak), with veins. States: protected (dirty or unpushed) moss, clean sage, stale dried-leaf tan; Free is a stippled field drawn at up to ⅔ of used space so a roomy disk still shows the leaves. The layout lives in `ArboristCore/Leaves` as a deterministic port of h8.js: power-diagram cells via half-plane clipping, sites moved to centroids and weights adapted toward target areas (in place of d3-voronoi-map), SplitMix64 seeded with "arborist", and h8.js's Park–Miller generator for waves and veins. Leaves have a minimum size (28 pt): two or more smaller items in a group fold into "other (n)"; a lone small item is padded up. "Clear N" shows the stale count and stays read-only: it copies the `git worktree remove` commands. Tapping a leaf gives Reveal in Finder and Copy remove command; a List toggle keeps the v1 list (and gives screen readers every item). App data (heart) is supported by the layout but the scanner doesn't produce it yet. `arborist render` writes the same geometry as SVG, for snapshots from Linux.

**D10. Menu bar icon is a wilting leaf (Joseph).** Four monochrome template glyphs (healthy, droop, wilted, dry outline) generated from `LeafGlyph` geometry, so they follow light and dark mode. Stage = free space vs multiples of the low-space alert: healthy above 3×, droop 1.5–3×, wilted 1–1.5×, dry below 1× (a value on a boundary takes the healthier stage). Multipliers are `leafStages` in `~/.config/arborist/config.json`; `showFreeText` (default on) keeps the free-space text next to the icon. Accessibility label: "Arborist: leaf <stage>, <n> GB free". Strip: `project-context/shots/leaf-stages.png`.

**D11. Progressive, bulk-listed, cached and time-limited scans (Joseph's Mac stuck on "Scanning…" for 2+ minutes).** `sample` showed the time going to `DiskUsage.treeSize` in disk wait. Changes:
- **One walk, bulk listing.** `DirLister` lists each directory once: `getattrlistbulk` on macOS (names, types and allocated sizes in one call per batch), `readdir` + `fstatat` on Linux, FileManager with prefetched keys as the fallback. `measureWorktree` sums rebuildable folders as it walks them (nested node_modules/.build inside one are not walked again) and spots nested repos from the listing it already has, with no extra `.git` stat. The per-file `resourceValues(Set)` calls are gone.
- **Linux sizes fixed as a side effect.** swift-corelibs reports allocated size as st_blocks × st_blksize, which is 8× too big on 4 KB-block filesystems. Linux now uses st_blocks × 512, which matches `du`. macOS sizes are unchanged.
- **Progress.** `Scanner.scan(cancel:onEvent:)` and `events(timeout:)` (an AsyncStream) report `.volume` (immediately), `.discovered(n)`, `.repo` as each repo's worktrees all finish, `.caches` and `.finished`. The app shows free space at once, fills the map repo by repo (relayout coalesced to every 0.4 s) and shows "12/34 repos". `scan()` (the CLI) returns the same result and JSON as before.
- **Cache.** The last finished scan is written to `~/Library/Caches/arborist/last-scan.json` (`$XDG_CACHE_HOME`/`~/.cache/arborist` elsewhere). On launch it is drawn immediately and marked "Cached" until the fresh scan finishes. Fresh repos replace cached ones as they arrive. An unreadable cache is ignored.
- **Timeout.** `scanTimeoutSeconds` (default 180) in config. `Deadline.run` runs the scan on its own thread and races it against the deadline. On timeout it sets a `CancelFlag` that the walkers and workers check, and the app shows the error with **Retry**, keeping the last results. The caller never waits on a stuck worker.
- **Sendable warnings.** In `checkLowSpace`, the notification body is built on the main actor before the callback, and `UNUserNotificationCenter` is fetched inside it. Nothing non-Sendable is captured.

**D12. Worktree-first map (Joseph: "focus on the worktrees I have across my computer, not just show storage").**
- **Every leaf is a worktree**, the main checkout included, grouped by repo. Caches, app data and node_modules are no longer leaves. A worktree's rebuildable folders are a darker inner leaf (its outline scaled about the centroid so the area matches the share, capped at 90% so a rim of source always shows). Caches move to one text line under the map ("Caches · pnpm 12.1 GB · …"). The free leaf is gone; the free bar stays.
- **Area = 0.6 + √GB**, not bytes, so a 50 MB worktree stays visible and clickable next to a 12 GB one.
- **Labels:** branch first, the repo in small italics under it when it fits ("feat-t5b-handover · property-management" in text form). A lone leaf too small for its repo line gets the repo as an edge label.
- **Status** (`Worktree.status`), in precedence: uncommitted → unpushed → merged → stale → clean. Uncommitted or unpushed always wins the colour, so work is never shown as safe to clear. Colours: moss = uncommitted/unpushed, sage = clean, tan = merged/stale.
- **Discovery across the Mac.** Default roots are `~` and `/tmp` (resolved, so `/private/tmp` counts once). A saved old default (`~`, `~/Documents`) is migrated. Depth 4 still reaches `~/conductor/workspaces/*`. Skipped: hidden folders, rebuildable folders, Pods/vendor/__pycache__/site-packages/bower_components, and under `~`: Library, Applications, Pictures, Movies, Music, Desktop, Downloads and Public, unless one is named as a root. Desktop and Downloads are skipped so there are no macOS privacy prompts. A `.git` file is followed to its main repo, so a linked worktree found anywhere brings in its repo, and `git worktree list` from each repo finds linked worktrees outside the roots. Repos are deduped by main repo. Unreadable folders are counted in `skippedPaths` and otherwise ignored. No Full Disk Access.
- **Fewer git calls.** Per repo: rev-parse, `for-each-ref` for tips and `--merged`. Per worktree: `log -1 --format=%cI%x1f%s` and `status --porcelain=v2 --branch`, which give dirty, the file count, the upstream and ahead/behind together. A reflog call is made only when the tip equals the default branch tip. Before this it was about 5 calls per worktree.
- **Hover.** The hovered leaf lifts, gets an outline and a shadow, and the others dim to 50%. A card shows branch · status, repo, path, last commit (age · subject), ↑ahead ↓behind vs upstream, uncommitted files, size · rebuildable and the action. Click = Reveal in Finder. The right-click menu adds Copy `git worktree remove`. Read-only. The List row for the same worktree is highlighted (one shared `hovered` path).
- **List** = every worktree, sorted by status rank then newest commit first (undated last).
- **Header** = "40 worktrees in 34 repos · 5 stale".
- **JSON** keeps every old key and adds `lastCommitSubject`, `upstream`, `ahead`, `behind`, `uncommittedFiles`.

**D13. Declutter, a calmer hover, and a hover card with hierarchy (Joseph: "the UI is getting cluttered and hard to read, plus the hover is very jarring").**
- **Group labels** sit only on the top and bottom edges of the map. A label is kept only if its measured box lies inside the map and is at least 6 pt from every label already kept. Bigger groups go first, and losers are dropped rather than nudged. Rotated side labels are gone.
- **Leaf text** is the branch name on one line at 10.5 pt, and only if the leaf is wide enough at the text's top, middle and baseline (`LeafText.fits`, with a slightly generous width estimate). Otherwise the leaf has no text. Sizes and the repo name are no longer on leaves; they are in the hover card.
- **Every worktree keeps its own leaf.** Small and 0 B ones (prunable `/tmp` worktrees) are padded to a fixed minimum area of about 28×28 pt and never folded into "other".
- **Quieter map.** The rebuildable inner shade is at about half its old opacity, veins are about 40% lighter, and the gutters are about 1 pt wider.
- **Footer.** One legend line with three dots and "Caches 7.1 GB" at the right. The Worktree/Main checkout row is gone. The free bar is unchanged.
- **Hover (app).** Changes ease in and out over 180 ms. Other leaves fade to 0.88 opacity with no darkening. The hovered leaf scales to 1.03 with a soft shadow. The card fades in and sits beside the leaf (right, left, below, then above) so it doesn't cover it. `HoverTracker` holds a leave for 120 ms, so crossing a gutter to a neighbour cross-fades and the card just moves. Pointing at the card keeps it open. With Reduce Motion there is no scale, lift or shadow, just a 100 ms opacity change.
- **Hover card.** Header: the branch (semibold), a state pill coloured like its dot, the repo, and the path in small monospace, shortened in the middle, with the full path as a tooltip. Then a 2×2 grid: Size (with a rebuildable mini bar), Changes, Sync ("1 ahead · 766 behind") and Last commit ("6 months ago"). The commit message wraps at word boundaries to at most 2 lines. The footer has subtle Reveal in Finder and Copy remove command buttons. Type is 10–12 pt, with 10 pt padding.

**D14. The app can remove safe worktrees after you confirm (Joseph approved, relayed by Cedric). This replaces D2's "no deletes" for the app only; the CLI stays read-only.**
- **Safety rule** (`Cleanup.blocker`). A worktree can be cleared only if all of these hold:
  - it's not the main checkout and not locked
  - it has no uncommitted files and no unpushed commits
  - it's merged into the default branch or its upstream is gone
  A worktree whose folder is missing (prunable) only gets a prune. Disabled buttons show the reason: "5 uncommitted files", "Unpushed commits", "Main checkout", "Locked" or "Not merged".
- **Entry points (UI clicks only).** "Clear N" (N = items in the plan), "Remove worktree" in the hover card, and Remove in the List row and its right-click menu. Each opens a confirm sheet listing branch, repo, path and size, plus the total freed. Cancel is the default button and Remove has no shortcut. There's no CLI subcommand, URL scheme, AppleScript or notification action.
- **Execution** (`Cleanup.execute`). Everything is checked again right before each item: still a worktree of that repo, not the first (main) entry, not locked, folder exists, HEAD unchanged since the scan, no uncommitted files, nothing ahead. Anything that changed means the item is skipped with the reason. Then it runs `git -C <repo> worktree remove <path>` (never `--force`) followed by `git worktree prune`. Prune-only items run just `git worktree prune`, and are skipped if the folder came back. Branches are never deleted, so commits on an upstream-gone branch survive. git runs from an argument array, with no shell.
- **Afterwards.** Results ("Removed / Pruned / Skipped / Failed") and the space freed are shown in the popover, then it rescans. Each removed or pruned item gets one tab-separated line in `~/.config/arborist/cleanup.log`: ISO-8601 local time, action, bytes, repo, branch, path.
- **Boundary.** All removal code is in the `ArboristCleanup` target. Only `ArboristApp` (and tests) depend on it. `CleanupTests.testCLICannotReachTheRemover` checks that Package.swift's `arborist` and `ArboristCore` targets don't list it, that no CLI source imports it, and that Core has no `worktree remove` call.


## D15: Hover that follows the pointer (2026-11-03)

**Bugs found.** (1) A stale card rect froze hover. On main, `cardRect` was set when a card appeared and never cleared, and any pointer inside it returned early. With the card at its farthest-corner slot (264×226 on a 448×400 map), about a third of the map, including the centre, either did nothing or kept the previously hovered leaf (often one far up-left) lifted while the pointer sat on another leaf. The card's own `onHover` re-asserted that old leaf too. (2) Gaps between the wavy outlines and the veins hit nothing, so hover went to nil and the 120 ms leave timer ran between neighbours. (3) The card was re-placed beside every leaf. (4) `.id(h).transition` overlays and several `asyncAfter` timers piled up on a fast sweep. (5) `onContinuousHover` may not fire in a MenuBarExtra window that isn't key.
- **One transform.** `MapTransform` (Core) is aspect-fit plus letterbox, with an optional origin, in top-left/y-down spaces. LeafMapView computes it from its real GeometryReader size, draws the layout through it, and maps every pointer and tap through `toMap` before hit-testing. The tracking view is the background of that same frame.
- **Pointer.** An NSTrackingArea (`.mouseMoved`, `.activeAlways`, `.inVisibleRect`) in a flipped NSView feeds `HoverModel`, the single source of truth. Each change is one transaction, and there is one cancellable settle.
- **Hit-test.** Inside an outline, or else the nearest edge within 10 pt (`LeafMap.hit`). It is sticky inside the map and clears 80 ms after the pointer leaves the map. It uses layout outlines only; the 1.03× lift and the shadow are drawing only.
- **Card.** A corner slot with hysteresis: it moves only when the hovered leaf would sit under it. It slides there and its content cross-fades. Unpinned it lets the pointer through and fades to 0.3 while under the pointer. A click pins it so its buttons work. Reduce Motion: no lift and no slide.
- **Test hook.** `--hover-sweep DIR` writes PNG frames and frames.json. It runs only in DEBUG builds and only with `ARBORIST_HOVER_SWEEP=1`. It doesn't create the menu bar item and runs with cleanup disabled (asserted). The CLI has `arborist render --hover-sweep DIR` (SVG frames, same frames.json).

## D16: Clear hover in far gaps (2026-11-03)

D15 kept the last leaf hovered anywhere inside the map. The leaf shapes don't fill their cells, so about half of a sweep's points land in gaps, and a leaf stayed lit with the pointer visibly in empty space.
- **Rule.** When the pointer is in a gap farther than the 10 pt snap radius from every leaf, hover clears after the same 80 ms grace. The deadline is set on entering the gap, so moving around inside it doesn't postpone the clear.
- **Cancelling.** Re-entering a leaf, or coming within the snap radius, cancels the clear.
- **Timer.** The app applies the clear with the same single cancellable timer, scheduled for the time remaining until the deadline.
- **Pinned card.** A pinned card stays until it is unpinned.
- **Sweep.** The sweep (instant mode) applies a pending clear by advancing time past the grace. In frames.json, `expected = underPointer ?? snappedTo`, and a mismatch is any frame where `hovered != expected`.
